# 支付、订单、续费与退款整改执行报告

## 目标

让咨询、律师入驻、律师续费和退款流程保持同一套规则：订单不串单，未支付订单 15 分钟后关闭，支付成功后订单/会员/通知一致，退款只允许在支付后 24 小时内申请。

## 已实现

1. 咨询订单唯一业务键改为“用户 + 民事/刑事 + 案件类型 + 三种套餐（基础/标准/高级）”。不同案件或套餐不会复用错误订单；同一业务键仍只保留一笔有效未支付订单。
2. 订单中心对 `pending` 和 `paying` 均显示继续支付入口；支付中订单复用原支付地址，过期订单关闭后可重新下单。
3. 律师续费按具体卡种隔离：民事季卡、民事年卡、刑事季卡、刑事年卡互不阻塞；民事律师可以购买刑事续费，反之亦然。
4. 续费回调按民事/刑事分别维护会员记录，总览到期日取有效会员的最晚日期；重复回调不会重复延长。
5. 支付回调优先读取微信独立签名头，兼容旧 Authorization 头；数据库更新失败返回失败，允许微信重试；首次支付成功才发送企业微信通知。
6. 用户端和管理员端均校验 `paid_at + 24 小时` 退款窗口；续费退款成功后撤销本次订单产生的会员记录，并重新计算剩余会员权益。
7. 修复后台律师支付状态把 `paid` 错映射为“待支付”的问题。

## 上线后的验收顺序

1. 确认 CloudBase 新部署构建成功并切换流量。
2. 执行并确认数据库迁移成功。
3. 用同一账号创建不同案件/不同咨询套餐，确认订单互不串联。
4. 验证 15 分钟未支付订单关闭，以及订单中心继续支付入口。
5. 验证民事律师购买刑事续费，检查两类会员到期时间。
6. 验证支付成功订单、支付时间、企业微信通知和会员权益同时更新。
7. 验证支付后 24 小时内可申请退款，超过 24 小时用户端和管理员端均拒绝。

## 回滚条件

若出现支付成功但订单/会员未更新、重复通知、跨案件串单、退款越过 24 小时或回调签名失败，立即将 CloudBase 流量回退到上一正常部署，并保留失败订单号和回调日志。
