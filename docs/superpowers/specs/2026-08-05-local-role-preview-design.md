# 本地角色预览与业务模拟设计

## 目标

让开发者在本机 VS Code 的本地预览中，直接以普通用户、守护者、认证律师或管理员身份进入受保护页面，并能完成提交资料、审核、接单和提现等操作的本地模拟。

该能力用于检查页面、交互与业务状态回显；不访问生产账号、生产数据、真实短信、真实支付或真实提现渠道。

## 范围

### 包含

- 本机开发模式下的测试身份选择入口。
- 四个固定测试身份及其初始演示数据。
- 本地数据中的资料提交、审核、接单、提现状态变更与回显。
- 本地“重置测试数据”操作，恢复固定初始状态。
- 短信、支付、提现请求的明确本地模拟成功结果。

### 不包含

- 修改生产登录方式、权限规则或真实用户数据。
- 连接生产 Supabase 数据库。
- 真实短信、微信支付、微信提现或外部回调。
- 将测试入口发布到预发布或生产环境。

## 方案

### 1. 环境隔离

本地角色预览只在 `DEPLOY_ENV` 不为 `PROD` 且 `NODE_ENV` 不为 `production` 时启用。

所有测试身份接口均在服务端再次检查该条件；不依赖前端隐藏入口作为安全保障。生产环境访问这些接口返回 404。

本地不配置数据库时，沿用项目已有的内存数据库实现。测试数据只保存在当前本地服务进程中，重启后自动清空；“重置测试数据”在当前进程内恢复固定状态。

### 2. 身份入口

新增一个只在本地开发模式渲染的小型“本地测试身份”面板。它提供：

- 普通用户：可查看登录后的用户页和普通咨询流程。
- 守护者：可进入守护者中心，查看邀请、收益与提现状态。
- 认证律师：可进入律师工作台，查看资料和待接订单。
- 管理员：可进入管理后台，审核律师申请。
- 重置测试数据：清除当前测试过程产生的变更，恢复初始状态。

选择身份由服务端创建现有格式的本地签名令牌；前端仍使用现有的令牌验证和受保护路由机制。不会在浏览器中伪造权限，也不会改动生产登录接口。

### 3. 初始测试数据

测试数据固定使用明显的演示名称和虚构手机号，不包含真实个人信息：

- 一名普通用户；
- 一名守护者及邀请、收益、可提现余额；
- 一名已审核通过的认证律师及一条待确认订单；
- 一条待审核的律师申请，供管理员完成审核；
- 一名本地管理员。

测试数据通过项目既有的数据访问层提供，避免页面各自写死假数据。

### 4. 本地模拟边界

涉及外部服务的流程只在本地替代最终外部动作：

- 短信验证：本地直接视为验证通过，并标注为“本地模拟”。
- 支付：本地把订单推进到支付成功状态，不调用支付渠道。
- 提现：本地创建或更新提现记录为成功，不调用微信或银行渠道。

资料提交、后台审核、订单接单等不依赖外部服务的状态变更，仍使用原有本地 API 与数据访问路径执行。

### 5. 验证

- 自动化测试覆盖：生产环境下测试接口不可用；四种身份得到正确令牌；重置后恢复初始数据。
- 本地运行类型检查与相关测试。
- 在 VS Code 集成浏览器逐一验证：身份切换、守护者提现模拟、律师接单、管理员审核、重置数据。

## 风险与控制

最主要风险是测试入口或特权令牌进入线上。控制措施是双层环境检查：入口不渲染，服务端接口也拒绝；测试令牌仅由本地接口签发且不使用生产数据。

第二个风险是演示流程与正式流程不一致。控制措施是只模拟短信、支付与提现等外部边界；其余页面和业务状态通过原有 API 路径与数据访问层执行。
