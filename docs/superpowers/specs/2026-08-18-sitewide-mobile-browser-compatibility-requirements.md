# 帮帮问法全站移动端浏览器兼容修复需求

## 1. 文档目的

本需求用于解决百度浏览器、微信内置浏览器及部分旧版移动浏览器中出现的全站样式异常问题。

本次范围不是只修复首页，而是确保网站所有公开页面、登录页面、用户页面、律师页面、守护者页面和管理页面在移动端都能正常显示和操作。

## 2. 当前问题

在部分移动浏览器中，页面内容可以加载，但样式没有完整生效，表现包括：

- Logo 或图片被放大；
- 顶部导航、底部导航或菜单布局错乱；
- 按钮被挤到下一行或无法正常点击；
- 卡片、表单、弹窗宽度异常；
- 文字过大、截断、重叠或溢出；
- 页面出现横向滚动；
- 图片、轮播图或媒体区域比例异常；
- 登录、支付、申请、审核等页面的操作区域显示不完整。

页面能够加载说明服务器、域名和基础接口不是本次问题的主要原因，主要问题是部分浏览器没有完整应用当前现代 CSS，以及旧浏览器备用样式覆盖范围不足。

## 3. 修复目标

在不改变业务流程和数据逻辑的前提下，让整个网站在移动浏览器中保持正确的视觉和交互效果。

目标浏览器包括：

- iPhone 百度浏览器；
- Android 百度浏览器；
- 微信内置浏览器；
- iPhone Safari；
- Chrome 移动端；
- 夸克等常见移动浏览器。

## 5. 修复内容

### 5.1 公共布局

为全站公共 Header、Footer、导航、菜单、弹窗和容器增加兼容样式，确保：

- Logo 使用固定且合理的宽高；
- 图片不会按原始尺寸撑开页面；
- 导航在手机端自动切换为移动布局；
- 菜单按钮始终可见且可点击；
- Header 不会遮挡页面内容；
- 页面不会产生横向滚动。

### 5.2 图片和媒体

统一处理普通图片、Next 图片、头像、Logo、二维码、轮播图和上传预览：

- 图片最大宽度不超过容器；
- 图片高度不会撑破布局；
- 保持适当的裁剪或等比例缩放；
- 图片加载失败时不破坏页面结构。

### 5.3 表单和按钮

确保登录、注册、申请、支付、审核、接单、提现等页面：

- 输入框宽度适配手机屏幕；
- 按钮不会超出屏幕；
- 主要按钮高度和点击区域足够；
- 多个按钮在窄屏下自动换行；
- 错误提示不会被遮挡；
- 键盘弹出时表单仍可操作。

### 5.4 卡片、弹窗和抽屉

- 卡片宽度不超过屏幕；
- 弹窗最大宽度适配手机；
- 抽屉和底部菜单可以完整滚动；
- 弹窗关闭按钮始终可见；
- 长文本和审核意见可以换行。

### 5.5 文字和字体

- 标题、正文、按钮文字在小屏幕上不溢出；
- 中文文字正常换行；
- 不依赖某个特定字体才能保持布局；
- 字体加载失败时使用安全备用字体。

### 5.6 旧浏览器兼容模式

完善现有旧浏览器备用样式，覆盖公共布局和所有页面类型，而不只覆盖首页 Hero 区域。

兼容规则应至少覆盖：

- Header 和 Footer；
- 导航和移动菜单；
- 页面容器；
- 图片和媒体；
- 表单、按钮和提示；
- 卡片、弹窗和抽屉；
- 表格和订单列表；
- 登录、支付、审核和后台页面。

## 6. 不修改范围

本次不修改：

- 登录注册业务逻辑；
- 支付业务逻辑；
- 审核、接单、提现业务逻辑；
- 数据库结构和数据；
- API 接口协议；
- 域名、服务器和部署平台；
- 页面业务文案；
- 桌面端现有设计意图。

## 7. 实施原则

1. 优先修复公共布局，避免每个页面重复处理。
2. 兼容样式只在需要的浏览器模式下生效，不影响现代浏览器。
3. 不通过隐藏内容或删除功能来掩盖布局问题。
4. 不使用浏览器特判破坏正常页面，只增加必要的兼容规则。
5. 先本地验证，再提交 GitHub，由 Zeabur 自动部署。

## 8. 验收标准

### 8.1 全站视觉验收

在目标移动浏览器中打开上述所有页面时：

- Logo、头像和图片尺寸正常；
- 导航和菜单布局正常；
- 页面没有横向滚动；
- 内容没有重叠、截断或被遮挡；
- 卡片、弹窗和抽屉宽度正常；
- 文字能够完整阅读。

### 8.2 全站交互验收

以下操作区域必须可见并可点击：

- 登录、注册、退出登录；
- 民事和刑事咨询入口；
- 律师申请、重新申请和续费；
- 守护者加入、邀请和提现；
- 管理后台审核和订单操作；
- 支付、返回、关闭和重试按钮。

### 8.3 回归验收

修复后同时检查：

- iPhone Safari；
- iPhone 百度浏览器；
- Android 百度浏览器；
- 微信内置浏览器；
- Chrome 桌面端。

现代浏览器的现有页面不能出现新的布局变化。

## 9. 发布流程

1. 完善全站兼容样式；
2. 本地运行并检查主要页面；
3. 使用移动尺寸逐页验证；
4. 执行生产构建；
5. 提交并推送 GitHub；
6. 等待 Zeabur 部署完成；
7. 在线逐页复测；
8. 确认无误后正式保留版本。

## 10. 完成定义

只有当公共页面、用户页面、律师页面、守护者页面和管理页面在目标移动浏览器中均能正常显示和操作，并且生产构建、部署和线上回归测试全部通过，本需求才算完成。
